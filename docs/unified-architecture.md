# 统一作品底库

网页只有一套作品集合。`scripts/build-unified.mjs` 与前端共用 `dist/assets/canonical.mjs`，由14,532条来源索引、168条已有研究、空间研究与 `research-links.json` 构建统一作品身份，再附加覆盖同一身份集合的 `completion.json` 补全层。

## 身份与细节

来源记录保留原 QID。题名、作者和实体粒度都支持同一身份时，将已有研究附着到该 QID。证据不足、查询未覆盖或版本/组篇粒度存在冲突时，研究记录保留 `local:<研究ID>`，不会丢弃；旧研究 ID 作为详情链接别名继续有效。局部未合并的作品可能仍含待核重叠，因此统一记录数不是全球唯一作品总数。具体链接依据、候选与保留理由可下载并复现。

来源书目事实、来源规则议题候选、已有研究解释分别存储。研究解释不替换原始日期、体裁、标题、关系、别名与语言声明；来源完整对象保存在原 gzip 与详情分片中。`canonical-universe.json.gz` 是统一浏览索引及研究层快照，引用全部详细源记录；`bibliography-full.json.gz` 保留完整来源数据和关联实体。

## 所有视图

书目、作品库、时间轴、宇宙视图、议题与来源分类使用同一套统一 ID。全站搜索、研究层级、未知年份、空间、议题、分支、补全状态及具体缺失字段等筛选写入URL，跨视图保持。比较可接受任何统一记录，缺失维度显示待分类。

时间轴汇总全部已知发表纪年，并单列未知纪年。已研究作品优先使用其已有纪年及排序版本备注；来源最早年份候选单独保留并显示。出版时间不是故事时间。年度密度仅代表本底库。

空间判断使用原空间研究及逐字段已有知识补充；后者明确待独立核对。没有判断依据的记录进入“空间待分类”档案区；这一区的视觉位置没有天文学意义，不能从题名、年份、科幻分支或议题自动推断其星球。抽象场域和未知空间分别保留。旧版空间数据中标为 abstract 且置信为暂定的条目原来兼有“未定”含义，统一层将其移至待分类，并完整保留 original_spatial_evidence 原理由与原标签，不增加新的空间推断。

议题可同时有研究解释与来源规则候选，计数可能重叠。未知议题仍属于底库，在议题视图中有独立入口。历史文本、阅读路线与报告属于有依据的编辑内容；示例按钮指向统一详情，时代入口查询整个底库。

## 可复现

```sh
python3 scripts/link-research.py
node scripts/build-unified.mjs
node scripts/validate.mjs
node scripts/validate-unified.mjs
```

新增来源须保留其原始身份与导入范围。新增研究或修订判断须记录来源、核查状态、字段依据与实体链接；不因展示需求虚构未知信息。全量加载任何索引分片失败时，不发布部分数据为完整结果。

补全模型、状态与外部粒度保护见 [补全方法](completion-methodology.md)。基线审计和补充覆盖层分别归档，完整原字段不因补充而丢失。

## 核心问题及细分议题

`topics` 仍是多值宽泛导航类别，包含分别保存的原研究、知识补充与规则候选。`issue_analysis_status` 独立表示核心问题分析：`research_interpreted`、`knowledge_added_unverified` 或 `missing`；候选标签不会使状态变为已有分析。

`issue_facets` 保存每项 `label/question/basis`，`issue_facets_status` 单列知识待核。`issue_alternatives` 保留新增的不同核心解释，已有解释仍为展示值。知识记录的 `assertions` 保存原始逐批输入，避免合并丢失字段备注、来源或解释。此层不会自动填补时间、空间、科学或书目身份。

`issueStatus` 与 `facet` 是共享筛选，所有主要视图和URL均使用同一模型。议题地图的数量、细分标签、作品例子随当前筛选更新。专用 `issue-analysis.json.gz` 从完整统一模型生成，当前CSV也保留核心问题及全部细分问题结构。
